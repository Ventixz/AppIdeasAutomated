Site Checker with Time Scheduling

Watch a site, on a schedule, and report whether it's up or down over time. The interesting parts aren't the ping — they're the three things a naïve checker gets wrong: the scheduling is drift-free and skips a backlog of stale checks after a sleep instead of stampeding the target; a flip to "down" is only confirmed after N consecutive failures, so one dropped packet isn't an outage; and uptime is time-weighted, not a count of checks. The same engine runs under Node against live HTTP (see the README); here it replays scripted scenarios in simulated time so a day of monitoring plays out in seconds.

Interval is the simulated gap between checks (uptime math uses it); each tick here plays in a fraction of a second so you can watch hours go by. Confirm is how many consecutive bad checks it takes to call the site down — raise it and the “Flaky link” scenario stops registering outages.

About the data. A browser can't open arbitrary sockets or sit for real hours, so this demo replays scripted probe sequences (checker-fixtures.js) through the real engine (checker-core.js) in simulated time: each tick advances a virtual clock by the configured interval. The scheduling, confirmation and time-weighted uptime math are exactly what checker-node.js runs against live HTTP — only the probe and the clock change.

Built automatically by the daily Claude Code routine described in the repository README. See the project README; the engine lives in checker-core.js and is covered by tests.js (92 checks).
